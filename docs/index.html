FlyRank ML Internship Capstone

Refresh / Content Opportunity Scoring

Using observable content, visibility, freshness, and engagement signals to rank pages for human review and possible content-refresh actions.

Dhun Sehgal
Data Science | September 2026

Abstract

This capstone investigates whether observable content, visibility, freshness, and engagement signals can be used to rank pages for human review and possible content-refresh actions. The analysis uses 30,000 anonymized page-level records from the FlyRank ML Internship dataset and excludes direct label-derived fields and identifiers from the model features. A transparent baseline score is compared with a Random Forest classifier using a client-level held-out test split to reduce client-level leakage. The Random Forest achieved a Precision@50 of 0.6200 compared with 0.3200 for the baseline, corresponding to a 1.94× lift over the baseline, while the test-set declining base rate was 51.10%. The resulting ranked output is intended as decision support for editors, helping them prioritize pages for review rather than automatically deciding that a page should be refreshed.

1. Introduction / Problem Statement

The main problem I wanted to work on was deciding which pages should be looked at first when there are many pages that could potentially need a content review or refresh.

The unit of analysis is a page. The output is a ranked list of pages with a refresh-opportunity score and a reason for why the page may deserve attention. A human editor can then use this ranking to decide which pages to investigate first.

The cost of a wrong decision can work in both directions. Reviewing a page that does not need attention can waste editorial time, while missing a page that deserves review can mean missing an improvement opportunity.

I used multiple observable signals instead of relying on one metric. Machine learning helps combine these signals into a consistent ranking that can be used as a starting point for human review.

This analysis uses the anonymized starter dataset content_refresh_anonymized.csv, containing 30,000 page-level records and 44 original columns. I used the page-level starter dataset directly rather than querying the full warehouse release.

The dataset provides observable signals covering search demand, competition, content characteristics, visibility, traffic, freshness, and engagement. The performance features include 90-day and 30-day aggregate windows.

The analysis uses the page-level CSV as its data table. No warehouse tables were directly queried for the final capstone model.

The final model features were:

search_volume, competition, cpc, word_count, char_count, impressions_90d, clicks_90d, pageviews_90d, sessions_90d, users_90d, engaged_sessions_90d, scroll_events_90d, content_age_days, days_since_last_update, ctr, avg_position, engagement_rate, scroll_rate, ai_traffic_pct, content_type, and main_intent.

Data exclusions and leakage checks

I excluded trend_direction because it was used to create the target. I also excluded trend_pct because it contains direct trend information. Using either of these as model features could leak information about the outcome.

content_id was treated as an identifier and was not used as a feature. client_id was also not used as a feature; it was used only for creating the client-level train/test split.

I also checked the train/test setup for client overlap. The final split contained no clients shared between the training and test sets, reducing the risk of client-level leakage.

The analysis does not report client names, domains, private queries, credentials, or other client-identifying information.

3. Methodology

I first created a simple rule-based baseline and then compared it with a Random Forest model.

Target

A page was labelled as declining when trend_direction was equal to down. All other pages were treated as non-declining.

Baseline

The baseline combines visibility, freshness, search position, and content depth signals. The final score was calculated as:

0.40 × visibility + 0.30 × freshness + 0.25 × position + 0.05 × depth

This gave a simple and interpretable ranking that could be understood without a machine learning model.

Random Forest

I used a Random Forest classifier with 300 trees, random_state=42, and balanced class weights. Numerical features were median-imputed and categorical features were filled using the most frequent value and one-hot encoded.

Validation design

I used GroupShuffleSplit with test_size=0.20 and random_state=42. The grouping variable was client_id, which means pages from the same client were not placed in both the training and test sets.

The training set contained 23,837 pages from 25 clients, while the held-out test set contained 6,163 pages from 7 clients. There was zero client overlap between the two sets.

The held-out test set contained 6,163 pages from 7 clients, while the training set contained 23,837 pages from 25 clients. There was zero client overlap between the two sets.

The declining base rate in the test set was 51.10%. This is important because Precision@50 should be interpreted alongside the underlying class rate rather than on its own.

The Random Forest placed 31 declining pages in its top 50 ranked pages, compared with 16 for the baseline. The relative lift over the baseline was 1.94×.

5. Interpretation

The feature-importance results showed that visibility, search position, content age, content length, and click-through behaviour were among the more informative signals in the model.

Some of the stronger features included impressions_90d, avg_position, content_age_days, char_count, word_count, and ctr.

I also found that some simple relationships were weaker than I might have expected. Word count and impressions had a weak positive correlation of about 0.163. The relationship between average position and CTR was also very weak, at about -0.073.

These results suggest that no single feature should be treated as the explanation for decline. The model is combining several signals to create the ranking.

Feature importance shows which signals were useful to the model. It does not show that changing a particular feature will cause a page's performance to improve.

6. Limitations & Honest Framing

There are several limitations to this analysis. The target is based on the observed declining label, so the model is learning to identify pages associated with that label rather than directly predicting the effect of a future content refresh.

The model also does not tell an editor exactly why a page declined. A high ranking should therefore be treated as a reason to investigate a page, not as proof that the page needs a specific change.

Most importantly, this analysis is not a causal experiment. The results cannot be used to claim that refreshing a page will improve its future performance.

I therefore treat the results as directional and as decision support for prioritizing human review.

8. Reproducibility

I kept the main analysis in the capstone notebook so that the steps can be followed and run again from the notebook. The complete repository contains the supporting assignment work, the capstone notebook, and the deployed paper.

Repository: https://github.com/24f2001824/ml-flyrank

Capstone notebook: work/notebooks/capstone.ipynb

The main steps to reproduce the analysis are:

  1. Clone the repository.
  2. Open work/notebooks/capstone.ipynb.
  3. Make sure the anonymized FlyRank dataset is available at data/raw/content_refresh_anonymized.csv.
  4. Run the notebook from top to bottom.
  5. The notebook loads the data, creates the target, checks for leakage, creates the baseline, trains the Random Forest model, evaluates both methods, and generates the ranked recommendations.

The main Python libraries used include pandas, numpy, scikit-learn, matplotlib, and seaborn.

The random seed is fixed at 42 for the train/test split and the Random Forest model. I used a client-level split with GroupShuffleSplit, so pages from the same client do not appear in both the training and test sets.

The evaluation is based on a held-out client-level test set. I report the resulting metrics in this paper rather than presenting the results as a causal experiment. The analysis is intended as a decision-support ranking tool for identifying pages associated with the declining label in the available data.
